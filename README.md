# NMS — Newspaper Management System

Offline Android newspaper register built with Expo SDK 57, React Native and TypeScript. Requirements and approved designs are in [Plan.md](Plan.md). Current verification and pilot status are in the [verification checklist](verification/README.md).

## Run

Install dependencies with `npm ci`. For an Expo Go preview, use `npm start` (Expo Go SDK 57). Screens, data entry, import and manual backup work in this preview; incoming Android shares and background scheduling need a native development build.

`index.js` registers the backup task before loading Expo Router (`app/`). Shared controls live in `src/components`, billing/import/report/recovery rules in `src/domain`, and device persistence/file operations in `src/data`.

On this Windows PC, a local Android 15 emulator named `NMS_Phone` is installed. Start it with:

```powershell
& "$env:LOCALAPPDATA/Android/Sdk/emulator/emulator.exe" -avd NMS_Phone -no-snapshot-load -gpu swiftshader_indirect
```

For a native development build:

```powershell
$env:ANDROID_HOME = "$env:LOCALAPPDATA/Android/Sdk"
$env:JAVA_HOME = "$env:LOCALAPPDATA/Android/Java/jdk-21.0.13+9"
$env:PATH = "$env:JAVA_HOME/bin;$env:ANDROID_HOME/platform-tools;$env:PATH"
npm.cmd run android
```

For subsequent JavaScript-only changes, run `npm run dev`. Native config changes require rebuilding. `android/` is generated by Expo prebuild from `app.json`; do not put permanent configuration only in generated files. The development Android package is `com.praveenbenny.nms`.

## Checks and evidence

```powershell
npm.cmd run typecheck
npm.cmd test
npx.cmd expo-doctor
npx.cmd expo export --platform android --output-dir dist-check
```

Automated tests cover billing carry, partial payments, selected-month payments, advance reversal, special-price expiry, write-offs, historical ordering, import review and incremental inserts, and backup checksums/images. They run compiled domain code with Node's test runner.

`verification/fixtures/temple-road.xlsx` is synthetic test data: 42 households, 56 newspaper copies and ₹2,400 in opening dues. Recreate it with `node verification/fixtures/create-workbook.cjs`. Never treat its prices or names as the real register. Captured emulator evidence is under `verification/screens/`; task completion is tracked in the plan.

## Storage and backups

The register is one versioned, validated aggregate in SQLite, written transactionally. Payment images are app-private files. Money is stored in integer paise. Existing monthly bills retain their snapshots when a household moves or catalog prices change.

An `.nms` backup is a ZIP containing the register, referenced payment images and a checksummed manifest. Restore validates the archive first, creates a safety copy of the current register, writes images under fresh names, then replaces SQLite state. The manifest records backup time and last register change. Current memory limits are 250 MB compressed / 500 MB expanded per restore; the pilot must test realistic image volume.

Local automatic backup checks run when NMS opens, and the native build requests periodic background work during the night. Android determines execution timing. Keep an exported copy outside the phone to survive loss of the device.

**Google Drive OAuth and automatic upload are deferred by the user.** The share/export menu can save a manual copy to Drive when its Android app is available. Future automatic integration needs a Google Cloud project, Android OAuth client/package/signing configuration, limited `drive.file` scope, secure credential storage, upload retry/idempotency and replacement-phone restore testing. Credentials must never enter backup files.

# Native emulator build note

The installed Expo SQLite 57.0.5 precompiled Android artifact contains only ARM64. `package.json` therefore builds `expo-sqlite` from source so the x86-64 emulator receives its native SQLite library. This uses [Expo Autolinking buildFromSource](https://docs.expo.dev/guides/prebuilt-expo-modules/); the first native build can take longer while Android downloads the required NDK.
